# カタログ管理画面

管理画面はヘッダーの「管理画面」から開きます。カタログはサーバーへ送信せず、その端末のlocalStorageに保存します。

## ツリー構造

左側のCATALOGツリーでは、メニューを次のような階層で管理できます。

```text
ランチメニュー/
  バーガー/
    チキンフィレバーガー/
      チキンフィレバーガーセット
レッドホットチキン/
  レッドホットチキン食べ比べ
```

標準カタログでは検証用に、既存のカテゴリ配下を「バーガー」「ツイスター」、さらに製品種類ごとの階層へ自動整理しています。例えば`ランチメニュー/バーガー/チキンフィレバーガー`、`セットメニュー/ツイスター/てりやきツイスター`として表示されます。旧形式の`category`だけを持つJSONや、先ほどの2階層形式も、読み込み時にこのルールで移行されます。

メニューの「階層パス」に`/`区切りで入力するか、左上の入力欄から階層を追加します。階層を選んで「階層設定」を開くと、階層名の変更・無効化・空の階層の削除ができます。階層名を変更すると、配下のメニューと子階層も一緒に移動します。

階層・メニューの右側にある「有効」「無効」ボタンで計算対象を切り替えます。無効化された階層の配下は、子階層やメニューを個別に有効にしても最適化対象になりません。ツリーの矢印で階層を折りたためます。折りたたみ状態は表示だけの設定で、計算結果には影響しません。

## メニューと単品ベクトル

メニューは次の構造です。

- `items`: 最適化で指定できる単品ベクトル名。
- `path`: メニューが所属する階層の配列。`ランチメニュー/フィレバーガー`は`["ランチメニュー", "フィレバーガー"]`です。
- `groups`: セット内の選択グループ。
- `options`: グループ内の単品ベクトルと価格差。
- `attributes`: メニューが持つ属性。
- `requires_any_attributes`: いずれかの属性を持つメニューを1つ以上購入した場合だけ使用できる購入条件。

各グループから`choose_count`個を選び、組み合わせを展開してsolver-ready vectorを生成します。生成数には上限があります。

例えば、トクトクパックには`attributes: ["pack"]`を設定し、ポテト2個390円には`requires_any_attributes: ["pack"]`を設定します。この場合、トクトクパックの購入数が0ならポテト2個390円は選択できません。管理画面では属性と購入条件をカンマ区切りで編集できます。

単品ベクトルは使用中のメニューがある場合は削除できません。先に該当する選択肢を変更してください。

## プリセット

プリセットにはメニュー定義、単品ベクトル、階層の無効状態、メニューの無効状態がまとめて保存されます。

標準プリセットとして次の2つを用意しています。

- `ランチメニュー`: 標準カタログを有効化した状態。
- `ディナーメニュー`: `ランチメニュー`階層を無効化し、その他の通常価格側の階層を有効化した状態。

ヘッダーのプリセット選択で即時に現在のカタログへロードできます。管理画面下部では、編集中の状態を名前付きプリセットとして保存・ロード・削除できます。保存したプリセットは同じブラウザのlocalStorageに保存されます。

mainブランチの`config/menu_catalog.json`を更新した後、既存端末へ公開内容を反映するには「公開版を読み込む」を使います。この操作は端末内の現在のカタログを置き換えるため、必要なら先にJSONを書き出してください。

JSONの書き出し・読み込みを使えば、別端末へカタログやプリセット用の状態を移行できます。標準カタログを全端末へ配布する場合は、`config/menu_catalog.json`を更新してから静的ビルドを作成してください。
