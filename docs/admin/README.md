# カタログ管理画面

管理画面はヘッダーの「管理画面」から開きます。カタログはサーバーへ送信せず、その端末のlocalStorageに保存します。

## ツリー構造

左側のCATALOGツリーでは、メニューをフォルダー（階層）で管理できます。

```text
ランチメニュー/
  バーガー/
    チキンフィレバーガー/
      チキンフィレバーガーセット
レッドホットチキン/
  レッドホットチキン食べ比べ
```

標準カタログでは検証用に、既存のカテゴリ配下を「バーガー」「ツイスター」、さらに製品種類ごとのフォルダーへ自動整理しています。例えば`ランチメニュー/バーガー/チキンフィレバーガー`、`セットメニュー/ツイスター/てりやきツイスター`として表示されます。旧形式の`category`だけを持つJSONや、先ほどの2階層形式も、読み込み時にこのルールで移行されます。

標準の最上位フォルダーは、ランチメニュー、キャンペーン、セットメニュー、トクトクパック、チキン単品、サイドメニュー、ドリンク、キッズメニューの順で表示されます。バーガー系のサブフォルダーはバーガー、ツイスターの順です。未登録のフォルダーは登録順を維持します。

メニューの「フォルダーパス」に`/`区切りで入力するか、左上の入力欄からフォルダーを追加します。フォルダーを選ぶと、その直下に子フォルダーを追加できます。「フォルダー設定」では、フォルダー名の変更・無効化・空のフォルダーの削除ができます。フォルダー名を変更すると、配下のメニューと子フォルダーも一緒に移動します。

ツリー左端のドラッグハンドルを使うと、フォルダーやメニューを移動できます。フォルダーを別のフォルダーの中央へドロップすると配下へ移動し、上端・下端や行間のドロップラインへドロップすると同階層内で並び替えます。メニューをフォルダーへドロップすると所属先が変わり、別のメニューへドロップするとそのメニューの前へ並び替えます。最上位フォルダーへ移動する場合は、ツリー上部の「最上位フォルダーへ移動」へドロップします。

フォルダー・メニューの右側にある「有効」「無効」ボタンで計算対象を切り替えます。無効化されたフォルダーの配下は、子フォルダーやメニューを個別に有効にしても最適化対象になりません。ツリーの矢印でフォルダーを折りたためます。折りたたみ状態は表示だけの設定で、計算結果には影響しません。

## メニューと単品ベクトル

メニューは次の構造です。

- `items`: 最適化で指定できる単品ベクトル名。配列の順番が管理画面と最適化画面の表示順になります。標準カタログはチキン類、サイド類、バーガー・ツイスター類、その他の順です。
- `item_prices`: 単品ベクトルごとの単品価格。管理画面の単品ベクトル編集で登録します。
- `item_quantities`: 単品ベクトルが親ベクトルへ換算される数量。
- `item_parents`: 単品ベクトルの継承元。
- `path`: メニューが所属するフォルダー階層の配列。`ランチメニュー/フィレバーガー`は`["ランチメニュー", "フィレバーガー"]`です。
- `groups`: セット内の選択グループ。
- `options`: グループ内の単品ベクトルと価格差。ポテトは画面上でポテトS、ポテトL、BOXポテトから選択します。
- `attributes`: メニューが持つ属性。
- `requires_any_attributes`: いずれかの属性を持つメニューを1つ以上購入した場合だけ使用できる購入条件。

各グループから`choose_count`個を選び、組み合わせを展開してsolver-ready vectorを生成します。生成数には上限があります。

ポテトは最適化時に内部で`ポテト(g)`ベクトルへ変換し、ポテトS、ポテトL、BOXポテトをそれぞれ80g、160g、400gとして計算します。`ポテト(g)`は便宜上0円の単品ベクトルです。ポテト単品の価格はメニューの価格差で設定します。

例えば、トクトクパックには`attributes: ["pack"]`を設定し、ポテト2個390円には`requires_any_attributes: ["pack"]`を設定します。この場合、トクトクパックの購入数が0ならポテト2個390円は選択できません。管理画面では属性と購入条件をカンマ区切りで編集できます。

単品ベクトルは一覧の「有効」「無効」ボタンで切り替えられます。無効な単品は最適化画面の候補から外れ、その単品を含むメニューの該当バリエーションも計算対象外になります。使用中の単品を削除することはできないため、不要な場合はdisableを使ってください。

単品ベクトルはCATALOGとは別の専用ツリーに、同じ行形式で表示されます。単品名を選ぶと、右側で単品名と単品価格を編集できます。

## プリセット

プリセットにはメニュー定義、単品ベクトル、フォルダーの無効状態、メニューの無効状態がまとめて保存されます。

標準プリセットとして次の2つを用意しています。

- `ランチメニュー`: 標準カタログを有効化した状態。
- `ディナーメニュー`: `ランチメニュー`フォルダーを無効化し、その他の通常価格側のフォルダーを有効化した状態。

ヘッダーのプリセット選択で即時に現在のカタログへロードできます。管理画面下部では、編集中の状態を名前付きプリセットとして保存・ロード・削除できます。保存したプリセットは同じブラウザのlocalStorageに保存されます。

mainブランチの`config/menu_catalog.json`を更新した後、既存端末へ公開内容を反映するには「公開版を読み込む」を使います。この操作は端末内の現在のカタログを置き換えるため、必要なら先にJSONを書き出してください。

JSONの書き出し・読み込みを使えば、別端末へカタログやプリセット用の状態を移行できます。標準カタログを全端末へ配布する場合は、`config/menu_catalog.json`を更新してから静的ビルドを作成してください。
